# Knowledge Management 异常处理与错误码规范 (Error Handling Taxonomy)

## 1. 设计哲学
Knowledge Management 遵循 **“防御式编程”** 与 **“用户友好的失败”** 原则。异常不应导致程序崩溃，而应转化为可感知的 UI 状态。

## 2. 错误分层 (Layered Errors)

### 🟢 L0: 物理与持久化错误 (Infrastructure)
| 错误码 | 语义 | UI 反馈建议 | 处理策略 |
| :--- | :--- | :--- | :--- |
| `E001` | 磁盘空间不足 | “存储空间已满”弹窗 | 停止写入，引导清理。 |
| `E002` | 数据库损坏 | “数据索引异常” | 触发快照回滚流程。 |
| `E003` | 权限丢失 | “文件夹访问权限失效” | 重新触发安全书签授权。 |

### 🔵 L1: 业务逻辑错误 (Domain)
| 错误码 | 语义 | UI 反馈建议 | 处理策略 |
| :--- | :--- | :--- | :--- |
| `E101` | 重复标题 | “标题已存在”文字提示 | 引导用户合并或修改标题。 |
| `E102` | 循环引用过深 | “拓扑关联过于复杂” | 提醒检查逻辑回路。 |

### 🟣 L2: AI 与 网络错误 (Application)
| 错误码 | 语义 | UI 反馈建议 | 处理策略 |
| :--- | :--- | :--- | :--- |
| `E201` | API Key 失效 | “AI 服务授权失败” | 跳转至设置页面。 |
| `E202` | 请求频率超限 | “AI 思考太快了，请稍候” | 开启指数退避重试 (Backoff)。 |
| `E203` | 语义上下文过长 | “文档内容超出单次处理上限” | 建议拆分文档。 |

## 3. UI 映射准则
*   **非侵入式**：使用 `AIPulseIndicator` 的变色或 Toast 提示（适用于 P1/P2 错误）。
*   **阻断式**：使用全屏 Modal 或 Alert（仅适用于 E001/E003 等导致不可用的 P0 错误）。
